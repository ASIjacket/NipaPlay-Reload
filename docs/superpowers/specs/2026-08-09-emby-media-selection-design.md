# Emby 媒体源与轨道选择设计

日期：2026-08-09

## 背景

当前 Emby 剧集播放流程在弹幕匹配完成后才创建 `PlaybackSession`，并且仅当返回的 `MediaSources.length > 1` 时临时弹出媒体源选择框。这个行为存在几个问题：

- 弹窗依赖播放流程和 Emby `PlaybackInfo` 的即时返回，出现与否不稳定。
- 用户无法在播放前独立查看版本信息。
- 媒体源选择没有持久化，下一次播放无法可靠恢复。
- `PlaybackMediaSource` 只保留少量字段，`MediaStreams` 仍以原始 Map 在 UI 中流转。
- 媒体源选择、字幕选择、音轨选择分散在详情页和播放器菜单中。

本设计将媒体配置从弹幕匹配和播放启动中拆出，仅针对 Emby 建立一个可测试的小模块。

## 目标

- 在 Emby 剧集页面提供独立的“版本与轨道”入口。
- 展示完整版本名、文件大小、总码率、视频参数、音轨和字幕信息。
- 支持选择媒体源、音轨和字幕；不支持同一文件内部的视频轨切换。
- 在本集、同番剧和全局三个层次自动记忆媒体源偏好。
- 以版本完整名称和发布源家族为主要继承依据。
- Windows 使用桌面对话框；iOS 使用全高底部面板。
- 点击剧集时直接按偏好播放，不再强制弹出版本选择框。
- 播放器内的 Emby 媒体源、音轨和字幕切换写入同一份偏好。

## 非目标

- 不修改 Jellyfin 的媒体源选择或偏好行为。
- 不新增 Android、电视或大屏模式的专用入口。
- 不实现单文件多视频轨道切换。
- 不修改 UA、代理、转码质量等无关设置。
- 不建立通用媒体服务器选择框架。

平台范围属于产品验收范围，不在源码注释中写入“仅适配某平台”或类似临时说明。源码注释只解释无法从代码本身看出的不变量与回退原因。

## 模块结构

模块包含五个职责明确的组件。

### EmbyMediaSourceCatalog

负责：

- 按需请求剧集 `PlaybackInfo`。
- 将响应转换为类型化媒体描述。
- 合并相同剧集的并发请求。
- 在详情页生命周期内缓存结果。
- 在页面刷新、服务器账户变化或显式重试时失效缓存。

剧集列表不预取整季 `MediaSources`。未访问的剧集只显示通用入口；有本地记忆时可以显示已保存的版本名。

### EmbyMediaPreferenceStore

负责：

- 读取和写入版本化 JSON。
- 按 Emby 服务器账户隔离数据。
- 保存本集精确选择、同番剧完整偏好及全局发布源偏好。
- 保存手动产生的音轨和字幕软偏好。
- 限制本集精确记录数量并淘汰最旧记录。
- 对损坏或未知版本数据安全回退。

### EmbyMediaSelectionResolver

纯逻辑组件，不依赖 Flutter UI 或网络。输入当前媒体源列表和已加载的偏好层，输出：

- 最终媒体源。
- 建议音轨和字幕。
- 选择依据。
- 是否发生回退。
- 是否应显示非阻塞提示。

### EmbyMediaSelectionController

负责面板状态和操作编排：

- 加载 Catalog 与 Store。
- 创建可取消的草稿选择。
- 切换媒体源后重新解析音轨和字幕草稿。
- 应用时一次性写入分层偏好。
- 取消时丢弃草稿。
- 暴露加载、错误、重试和保存状态。

### EmbyMediaSelectionPanel

只负责呈现 Controller 状态。Windows 与 iOS 使用不同容器，但复用相同内容组件和选择逻辑。

## 类型化媒体描述

`PlaybackMediaSource` 增加向后兼容的可空字段：

- `name`
- `size`
- `bitRate`

字段映射明确使用 Emby JSON 的 `Name`、`Size` 与 `Bitrate`；其中 `Bitrate` 映射到 Dart 字段 `bitRate`，避免大小写差异导致码率静默丢失。

Emby 专用描述层从 `mediaStreams` 构建：

- `EmbyVideoStreamDescriptor`
- `EmbyAudioTrackDescriptor`
- `EmbySubtitleTrackDescriptor`

视频摘要包含编码、配置、分辨率、帧率、位深、HDR 和码率。音轨包含流索引、语言、标题、编码、声道、采样率、码率及默认标记。字幕包含流索引、语言、标题、编码、内嵌/外挂、默认与强制标记。

播放器请求仍使用 Emby 返回的真实流索引；持久化层不跨剧集保存这些索引。

## 存储身份与结构

服务器账户键优先使用：

`ServerProfile.serverId + userId`

当远程服务器 ID 不可用时回退到本地 `ServerProfile.id`。服务器 URL 不参与主键，避免切换地址后丢失偏好。

使用单一版本化 SharedPreferences JSON，例如：

```json
{
  "version": 1,
  "accounts": {
    "server:user": {
      "global": {},
      "series": {},
      "episodes": {}
    }
  }
}
```

每次手动应用自动保存三种精度：

- 本集：精确 `episodeId -> mediaSourceId`。
- 同番剧：完整版本名、发布源家族、版本特征和技术特征。
- 全局：发布源家族及软技术偏好，不强制完整字幕封装一致。

本集记录带更新时间，用于有界淘汰。存储内容不包含访问令牌、服务器密码、媒体 URL 或完整服务器文件路径。

## 版本名称解析

完整版本名保留原样用于显示，同时生成归一化值用于匹配：

- 去除首尾空白。
- 合并连续空白。
- 对拉丁字符统一大小写。
- 统一常见分隔符，但不改写中文名称。

名称再拆为“发布源家族”和“版本特征”。

示例：

- `WEB-DL.Baha`：家族为 `Baha`，特征为 `WEB-DL`。
- `简繁日内封.喵萌奶茶屋&LoliHouse`：家族为 `喵萌奶茶屋`、`LoliHouse`，特征为 `简繁日内封`。
- `简体内嵌.喵萌奶茶屋`：家族为 `喵萌奶茶屋`，特征为 `简体内嵌`。

解析器识别常见分辨率、编码、发布格式和字幕封装词；未知的非技术词保留为家族候选。解析结果必须可解释，不使用不可追踪的模糊总分作为首要决策。

## 媒体源匹配规则

Resolver 使用确定的逐级规则：

1. 当前剧集存在已保存的精确 `MediaSourceId`。
2. 同番剧完整归一化版本名一致。
3. 同番剧发布源家族重合；多个候选时依次比较家族重合数量、字幕封装特征和视频技术特征。
4. 全局发布源家族重合；多个候选使用相同的稳定择优规则。
5. 分辨率、HDR、编码和容器最接近。
6. Emby 响应中的默认或首个媒体源。

文件大小与精确码率只用于展示和同条件下的弱择优，不作为硬匹配条件。

Resolver 返回结构化原因，例如“本集精确选择”“同番剧完整版本”“全局发布源”“Emby 默认”。UI 可以据此显示当前选择来源，日志也可以记录可解释结果。

## 音轨与字幕匹配

默认状态为“跟随该版本默认”。只有用户手动选择后才写入偏好。

音轨与字幕偏好使用与媒体源一致的作用域顺序：

1. 本集精确偏好。
2. 同番剧轨道指纹偏好。
3. 全局粗粒度轨道偏好。
4. 当前媒体源默认轨道。

本集记录可同时保存当集真实流索引和轨道指纹；跨剧集只使用指纹匹配，不复用原始索引。全局偏好只保留语言、标题关键词、编码、声道、内嵌/外挂等稳定特征。

音轨依次比较：

1. 语言与归一化标题。
2. 语言。
3. 声道布局与编码。
4. 当前媒体源默认音轨。

字幕依次比较：

1. 语言与归一化标题。
2. 语言。
3. 内嵌/外挂与字幕编码。
4. 当前媒体源默认字幕。

“关闭字幕”是明确的手动偏好，并按“本集 → 同番剧 → 全局”继承。用户手动应用“关闭字幕”时写入三层偏好；自动采用默认字幕时不产生记录。匹配不到相似轨道时回退到当前媒体源默认，不报错，也不阻止播放。

## UI 设计

### 剧集入口

- 剧集行或卡片的主体仍负责直接播放。
- 增加独立的“版本与轨道”操作，不复用整行点击。
- 有本地记忆时显示版本名称；否则显示通用文字。
- 打开入口不会触发弹幕匹配或启动播放。
- 入口只在当前服务器类型为 Emby、运行平台为 Windows 或 iOS、且未启用大屏模式时出现。
- 平台与模式判断封装为可测试的入口可用性规则，详情页不散落条件分支。

### Windows

使用桌面对话框：

- 左侧为媒体源列表。
- 右侧为“概览 / 音轨 / 字幕”页签。
- 媒体源第一行显示完整版本名。
- 第二行显示类似 `1080p · 505.4 MB · 2.8 Mbps` 的摘要。
- 底部提供“取消”和“应用”。

### iOS

使用 Cupertino 风格全高底部面板：

- 媒体源列表在上。
- 当前媒体源详情及页签在下。
- 底部固定“取消”和“应用”。
- 内容超出时由主体滚动，底部操作保持可见。

### 状态行为

- 首次打开显示加载状态。
- 请求失败时保留面板并提供重试。
- 切换媒体源只修改草稿，并重新解析轨道候选。
- “取消”不产生任何持久化副作用。
- “应用”保存偏好并关闭面板，不触发播放或弹幕匹配。

## 播放流程

点击剧集后：

1. 完成现有弹幕匹配流程。
2. 从 Catalog 获取或复用当前剧集媒体源快照。
3. Resolver 计算最终媒体源、音轨和字幕。
4. 使用解析后的 `mediaSourceId` 创建或刷新有效的 `PlaybackSession`；转码路径同时传入解析后的 Emby 音轨和字幕索引。
5. 启动现有播放器流程。
6. 直播放在播放器打开后，将轨道指纹映射到当前播放器暴露的实际轨道并应用。

旧的播放前强制媒体源弹窗被移除。Catalog 共享同一剧集的并发描述请求和新鲜元数据缓存。缓存不承诺复用 `PlaySessionId` 或播放 URL；最终播放仍可发起一次创建有效播放会话所必需的请求。

轨道应用分为三条明确路径：

- 转码：将解析后的 Emby 音轨、字幕索引传给 `createPlaybackSession`，保留现有烧录字幕参数语义。
- 直播放内嵌轨道：播放器打开后，以语言、标题、编码和声道等指纹匹配原生播放器轨道，再通过播放器抽象层激活；不能把另一集的 Emby 流索引直接当作原生轨道索引。
- 直播放外挂字幕：向现有外挂字幕加载流程传入解析结果。选择具体外挂字幕时只下载并激活匹配轨道；选择“关闭字幕”时清除并跳过自动激活；选择“跟随默认”时保留现有默认选择行为。

轨道解析结果使用类型化的 `ResolvedEmbyTrackSelection` 表达“跟随默认、关闭、具体轨道”三种状态，调用方不以可空整数猜测状态。

自动播放失败时：

- 依次尝试同番剧、全局和 Emby 默认候选。
- 成功回退后显示非阻塞提示。
- 所有候选均失败时沿用现有播放错误处理。

面板中的手动应用失败时不静默换源，保留面板并显示错误。

## 播放器内选择

播放器现有 Emby 媒体源、音轨和字幕切换继续工作。应用成功后通过同一个 Store 写入分层偏好；面板 Controller 与播放器菜单共享写入用例，但不互相依赖 UI 状态。Jellyfin 分支不调用新 Store，也不改变现有行为。

## 缓存与失效

- 缓存范围限定为当前详情页或同等短生命周期协调器。
- 缓存键包含缓存作用域和剧集 ID；通常使用服务器账户，身份不可用时使用不持久化的页面级作用域。
- 合并同一键的并发 Future，避免重复请求风暴。
- 页面刷新、账户切换和显式重试清除相关缓存。
- 缓存内容仅为类型化媒体描述与短时 `PlaybackInfo` 快照，不持久化最终 `PlaybackSession`。
- 播放会话失效或快照不兼容时重新请求，不持久化会话 URL 或 `PlaySessionId`。

## 错误与兼容

- 旧版本没有偏好数据时自然使用 Emby 默认源。
- JSON 损坏、字段缺失或 schema 版本未知时忽略对应记录。
- 保存失败必须反馈给 UI，不显示虚假的成功状态。
- 已保存的 `MediaSourceId` 不存在时继续执行名称和家族匹配。
- 名称为空时回退到文件 basename，再回退到容器和序号标签。
- 可选字段解析失败时只影响展示，不影响播放 URL 构建。

## 测试策略

实现严格按 Red-Green-Refactor 推进，测试先于生产代码。测试范围已确认：

### 单元测试

- JSON `Name`、`Size`、`Bitrate` 到 Dart 字段及各类流描述的解析。
- Baha、LoliHouse、组合字幕组和未知名称的家族解析。
- 本集、同番剧、全局、技术特征、Emby 默认的优先级。
- 精确 ID 失效、重名、多家族和无名称回退。
- 音轨、字幕软匹配及“关闭字幕”。
- 本集、同番剧、全局轨道偏好的覆盖顺序。
- 服务器账户隔离、损坏存储回退和有界淘汰。
- Catalog 并发请求合并与缓存失效。

### Widget 测试

- Windows 对话框的信息层级、页签、应用和取消。
- iOS 底部面板的信息层级、滚动、应用和取消。
- 加载、错误和重试状态。
- 切换媒体源后轨道草稿重新解析。

### 契约与集成测试

- Emby 播放会话收到解析后的媒体源、音轨和字幕参数。
- 转码路径把解析后的 Emby 轨道索引传入播放会话。
- 直播放在打开媒体后匹配并激活内嵌音轨和字幕。
- 直播放只下载并激活选中的外挂字幕。
- “关闭字幕”不会被现有自动字幕流程重新开启。
- 点击剧集不再调用媒体源选择弹窗。
- 自动回退不阻止可用候选播放。
- 播放器内 Emby 选择写入 Store。
- Jellyfin 行为和调用路径不变。

只运行与本功能和受影响边界直接相关的定向测试；新增生产代码覆盖率不低于 80%。

## 实施约束

- 详情页只保留入口和播放编排，不承载解析与持久化算法。
- Resolver 不导入 Flutter UI、Provider 或网络服务。
- Store 不依赖 Widget context。
- Catalog 不写偏好。
- UI 不直接操作 SharedPreferences。
- 不在源码注释中写平台适配范围或临时版本说明。
- 不修改无关 Jellyfin、代理、UA 或 Action 文件。
